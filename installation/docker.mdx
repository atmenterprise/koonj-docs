Provision a cloud host with access to your mounted filesystem and S3-compatible bucket. Use Docker Engine 24 or later with Compose v2. Allow at least 4 GB RAM and 20 GB disk space for the stack. The deployment guide recommends 8 GB RAM. Plan additional capacity for your own data.

## Configure the deployment

1. Download `koonj-<version>-koonj-deployment.zip` and `SHA256SUMS.txt` from the same [GitHub release](https://github.com/atmenterprise/koonj/releases), or [build the ZIP from source](/developers/local-development#build-the-deployment-zip). For a downloaded ZIP, run `sha256sum -c SHA256SUMS.txt` from the download directory. Extract the ZIP and enter its `docker/` directory.
2. Copy `.env.example` to `.env`.

   ```bash
   cp .env.example .env
   ```

3. Replace all `CHANGE_ME` placeholders in `.env`, including `KOONJ_DB_PASSWORD`, `KEYCLOAK_DB_PASSWORD`, `KEYCLOAK_ADMIN_PASSWORD` and `KOONJ_RABBITMQ_PASSWORD`.
4. Set `KOONJ_DATA_MOUNT` to the host directory you want to catalog. The server and transfer worker see it as `/mnt/koonj`.
5. [Configure Keycloak and the console origin](/installation/configuration#configure-keycloak) before starting the stack.

## Start and verify

```bash
docker compose up -d --build --wait
docker compose ps
curl -fsS http://localhost/actuator/health
```

Use the configured `KOONJ_UI_PORT` if you changed it from port 80. Open the same console URL in your browser and sign in. Compose starts the database, identity provider, API, transfer worker, notification worker, RabbitMQ, and web console. The notification worker shares the database with the API and uses RabbitMQ to deliver queued messages.

`docker compose down` stops the stack and preserves its named volumes. Start it again with `docker compose up -d --wait`. For an existing installation, review [database upgrades](/installation/operations#upgrade-an-existing-database) before replacing the stack.

## Enable observability

The standard stack leaves telemetry export disabled. In `.env`, set `OPENOBSERVE_ROOT_EMAIL`, `OPENOBSERVE_ROOT_PASSWORD`, and `OPENOBSERVE_AUTHORIZATION`. The authorization value is `Basic ` followed by the Base64-encoded `email:password` for ingestion. Set `KOONJ_OPENOBSERVE_URL` to the browser-facing OpenObserve URL, such as `http://localhost:5080/web`. Set `KOONJ_OPENOBSERVE_ORGANIZATION` if you use an organization other than `default`.

```bash
docker compose -f docker-compose.yml -f docker-compose.otel.yml up -d --build --wait
curl -fsS http://127.0.0.1:5080/healthz
```

Use both Compose files in subsequent commands. In Koonj, open **Administration → Observability**. Run a scan or transfer, then look for the `koonj.job.execution` trace, job execution metrics, and the `koonj_server` log stream.

When sign-in works, [register your storage](/guides/administration#storage-connections) and run the [quickstart](/quickstart).

To expose archived files through a native file manager, configure the [transparent recall gateway](/installation/recall-gateway).
