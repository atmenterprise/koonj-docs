## Prerequisites

Use JDK 21, Maven 3.9 or later, Node.js 22.12 or later with npm, and Docker Compose v2. Run the commands from the Koonj application source root unless a step gives another directory.

## Start the local stack

```bash
docker compose -f deploy/docker-compose.yml up -d --wait
```

This Compose stack starts PostgreSQL on port 5432, Keycloak at `http://localhost:8180`, and LocalStack S3 at `http://127.0.0.1:4566` by default. LocalStack provisions `koonj-local-archive` in `eu-west-2`. Set `KOONJ_LOCAL_BUCKET` and `KOONJ_LOCAL_REGION` before starting Compose to change them.

Build and install the shared notification model into your local Maven repository once before launching the API module. Repeat this step when you modify that module.

```bash
mvn -pl koonj-notification-model -am install
export KOONJ_DB_URL='jdbc:postgresql://localhost:5432/koonj?reWriteBatchedInserts=true'
export KOONJ_DB_USERNAME=koonj
export KOONJ_DB_PASSWORD=password
mvn -pl koonj-server spring-boot:run
```

The database password above is the development Compose default. Match any overrides you used to start PostgreSQL. The server listens on port 8080 and uses `KOONJ_DDL_AUTO=update` by default.

In a second terminal, start the UI.

```bash
cd koonj-ui
npm ci
npm run dev
```

Open `http://localhost:5173`. By default Vite proxies `/api/v1` to the API at `http://127.0.0.1:8080`. An absolute `VITE_API_BASE_URL` bypasses the proxy and requires the matching origin in `KOONJ_CORS_ALLOWED_ORIGINS`. For same-origin production builds, use `VITE_API_BASE_URL=/api/v1`.

Sign in with a development account defined in `deploy/keycloak/koonj-realm.json`, or use **Create Account** and assign a realm role in Keycloak. The default development Keycloak admin console is `http://localhost:8180/admin`. For the [quickstart](/quickstart), register a local test directory and a **Custom S3** connection with the LocalStack endpoint, bucket, and region above. Enable **Path-style access** and use the development access and secret keys `test`.

Run `docker compose -f deploy/docker-compose.yml --profile notifications up -d rabbitmq` if you need to exercise notification delivery. Configure the worker with the development settings in `deploy/.env.example` and start it after the API. Shut down the backing services with `docker compose -f deploy/docker-compose.yml down`.

## Find the code

| Module | Responsibility |
| --- | --- |
| `koonj-server` | Spring Boot API, storage connectors, catalog, job execution, authorization, and notification outbox. |
| `koonj-ui` | React and TypeScript console, Vite dev server, Keycloak sign-in, and client API services in `src/api`. |
| `koonj-notification-model` | Shared notification entities and repositories. |
| `koonj-notification-worker` | RabbitMQ relay, delivery routing, SMTP, and webhooks. |
| `koonj-fuse` | Linux filesystem view and transparent recall client. |
| `koonj-assembly` | Deployment ZIP for Docker and on-premise installs. |

Browse Swagger at `http://localhost:8080/swagger-ui/start` and retrieve OpenAPI JSON at `http://localhost:8080/v3/api-docs`. See the [API guide](/api/overview) for authentication and project scope.

## Run tests

```bash
mvn -pl koonj-server,koonj-notification-worker -am test
cd koonj-ui
npm test
npm run build
```

## Build the deployment ZIP

From the source root, run:

```bash
mvn -pl koonj-assembly -am clean package
```

Find `koonj-<version>-deployment.zip` in `koonj-assembly/target/`. Pass `-Ddeployment.version=1.0.0` to override the version in the ZIP name and its top-level directory. The archive contains `docker/` and `on-premise/` packages with the executable server, worker and FUSE JARs and compiled web assets.
